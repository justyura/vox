    关于 Vox

    Vox 把一段音频或视频变成可以阅读、可以跳转、可以学习的文字：上传之后自动转码和转写，按句子对齐时间戳，再把文中的生词标出来。

    系统架构

    用到的技术

    服务

    • Go
    • Gin
    • gRPC
    • Protocol Buffers
    • net/http

    对外 HTTP + JSON，服务之间 gRPC。

    数据与存储

    • PostgreSQL
    • pgx 连接池
    • goose 迁移
    • MinIO
    • 阿里云 OSS

    每个服务一个库；存储走 S3 兼容接口，预签名 URL 直传。

    异步任务

    • RabbitMQ
    • direct 交换机
    • 手动 ack
    • prefetch 1
    • 竞争消费者

    按阶段路由：转码、短转写、长转写各一条队列。

    媒体与语音

    • ffmpeg
    • whisper.cpp
    • cgo
    • Metal
    • ElevenLabs Scribe v2
    • ECDICT

    同一个 Transcriber 接口，本地和云端两种实现。

    前端与入口

    • 原生 JavaScript
    • nginx 反向代理
    • JWT 认证

    无框架、无构建；同源代理，不需要 CORS。

    部署与伸缩

    • Docker
    • Docker Compose
    • Kubernetes
    • KEDA
    • SSH 隧道

    KEDA 按队列长度自动扩缩 worker；内部端口只绑本机。

    常见问题

    使用上的问题在前，技术选择在后。

    使用

    支持哪些文件？

    常见的音频和视频都可以：mp3、m4a、wav、mp4、mov、mkv、webm 等。上传后会先统一转成 16kHz 单声道 WAV，再交给转写引擎。

    要等多久？

    10 分钟以内的音频交给云端 ElevenLabs，通常几秒到几十秒就能出结果。更长的交给本地 whisper 模型，需要排队，可能要几分钟；列表里的进度条会告诉你它在排队还是在处理。

    支持哪些语言？

    默认自动识别。也可以在上传区下方手动指定中文、英文、日语等，指定后识别会更准。

    为什么有的视频在网页里放不了？

    浏览器只认识 MP4 + H.264 + AAC 这类格式。MKV 容器或 E-AC3 音轨在浏览器里放不了，但转写不受影响，文字和生词照常生成。

    生词是怎么挑出来的？

    用开源词典 ECDICT 查每个词的考试标签和词频排名，过滤掉中考、高考、四级范围的基础词和最常用的 5000 词，剩下的按出现次数排序。每次打开页面实时计算，不保存。

    字幕能导出吗？

    可以。阅读页右上角的"更多"里可以下载 SRT 字幕和纯文本，都是根据时间戳在浏览器里当场生成的。

    我的文件存在哪里？谁能看到？

    存在自建的对象存储里，只有你自己的账号能访问。上传和播放都使用有时效的签名链接，链接过期后就无法再打开。

    技术

    为什么要用消息队列，而不是直接调用？

    转码要几十秒，转写要几秒到几分钟，用户不能一直等着一个请求返回。任务放进 RabbitMQ 后立即返回，worker 按自己的速度取任务；worker 崩溃或重启，任务也还在队列里，不会丢。

    服务之间用 gRPC，为什么生词服务用 HTTP？

    协议看调用方。01、02、03 之间是内部的 Go 服务互相调用，gRPC 有强类型接口，性能也好。生词服务要给浏览器和外部程序直接调用，而浏览器不能直接使用 gRPC，所以用 HTTP + JSON。

    文件为什么不经过后端服务？

    后端只负责签发有时效的 URL（控制面），文件字节由浏览器和 worker 直接和对象存储交换（数据面）。一个几百 MB 的视频不会占用 API 网关的带宽和内存，网关也就不会成为瓶颈。

    为什么按时长分成两条队列？

    短的要快，长的要省。云端 API 按时长计费（约每小时 0.22 美元），几十秒就出结果；本地模型免费，但慢。分开之后，短任务也不会排在两小时的长任务后面干等，也就是避免了队头阻塞。

    怎么扩容？

    worker 不保存状态，多开几个副本连到同一条队列就行，RabbitMQ 会把任务轮流分给它们（竞争消费者）。在 Kubernetes 上用 KEDA 按队列长度自动增减副本，队列清空后缩到零。

    Mac 关机了，长任务怎么办？

    队列是持久化的，任务会一直在 transcribe-long 里等着，Mac 重新连上后继续处理，不会丢失。
